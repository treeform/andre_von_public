babel.player.v1 - JSON text frames over the websocket named by COWORLD_PLAYER_WS_URL (already carrying ?slot=N&token=T). A Babel policy is a prompt: the player container's only job is to deliver it; the game server makes every decision by sending that prompt plus the seat's alphabet, private notes, own history, and the target (speaker) or the message and lineup (listener) to Claude. game->player frames: {"type":"welcome","protocol":"babel.player.v1","slot":N,"name":str,"rounds":int} on connect; {"type":"state","slot":N,"name":str,"seat":{score,correct,asSpeaker,asListener,roundsPlayed},"round":int,"rounds":int,"roundsPlayed":int,"started":bool,"done":bool,"reason":str} after every event - redacted to the seat's own tallies because Babel has hidden information (targets, lineups, notes, and the other pair's traffic are not for the seats; decisions are server-side so nothing is lost); {"type":"final","done":true,"scores":[...],"correct":[...],"asSpeaker":[...],"asListener":[...],"names":[...],"rounds":int,"reason":str} at episode end, after which the player should exit. player->game frames: {"type":"prompt","prompt":str,"scripted":bool} (prompt max 4000 chars; send after connect and again after welcome; the latest frame applies to all later calls; scripted:true plays the built-in code-and-decode baseline for this seat instead of the LLM). The published babel-player runnable reads its prompt from the PLAYER_PROMPT environment variable (PLAYER_SCRIPTED=1 for the scripted baseline), so a new policy is `coworld upload-policy` of the same image with --secret-env PLAYER_PROMPT="<your strategy>".
