gozu.player.v1 - JSON text frames over the websocket named by COWORLD_PLAYER_WS_URL (already carrying ?slot=N&token=T). A policy is just a prompt: the player container's only job is to deliver it; the game server makes every decision by sending that prompt plus the seat's view of the public table to Claude. game->player frames: {"type":"welcome","protocol":"gozu.player.v1","slot":N,"name":"<alias>","mode":"goofspiel"|"oshizumo","seats":int,"maxRounds":int} on connect; {"type":"state","slot":N,"name":"<alias>","round":int,"maxRounds":int,"roundsPlayed":int,"mode":str,"seat":{"score":float,"points":float,"spent":int,"hand":[int],"coins":int},"position":int,"started":bool,"done":bool,"reason":str,"ending":str} after every event, redacted to the seat's own resources - the past is public but the CURRENT round's bids are never in a frame before every bid is in (sealed bids, server-side); {"type":"final","done":true,"slot":N,"scores":[float],"points":[float],"names":[alias],"rounds":int,"reason":str,"ending":str} at episode end, after which the player should exit. player->game frames: {"type":"prompt","prompt":str,"scripted":"match"|"hoard"|true|false} (prompt max 4000 characters, truncated on a rune boundary; send after connect and again after welcome; the latest frame applies to all later rounds; a scripted value plays that built-in baseline for this seat instead of the LLM). The published goofspiel-oshi-zumo-player runnable reads its prompt from the PLAYER_PROMPT environment variable (PLAYER_SCRIPTED=match|hoard for the baselines), so a new policy is `coworld upload-policy` of the same image with --secret-env PLAYER_PROMPT="<your strategy>".
